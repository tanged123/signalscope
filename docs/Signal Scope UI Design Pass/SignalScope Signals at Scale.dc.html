AUDIT V3 SignalScope — signals at scale 2026-07-31 · build screenshot 01:10
Extends AUDIT v2 (chrome unchanged). Scope: selection, bulk customization, cross-source naming, and 100–10,000-signal scale. Root diagnosis first, then five mechanisms, then rollout.
1 · THE UNIT IS WRONG
diagnosis
Every current operation addresses one series at a time — click a chip, open a popover, set a color, repeat. With N channels × M sources that is O(N×M) clicks, an O(N×M) chip row, and an O(N×M) legend. No amount of layout polish fixes an operand problem. All four complaints (isolate · bulk edit · name drift · thousands) are the same complaint.
— Formalize the two dimensions the tree already hints at ("8 runs"): series = channel × source — channel: the semantic signal (derived/temp). source: run_01…run_08, bench.csv, a live bus. — Every mechanism below lets the operator address either axis, or a set spanning both. The single series stays reachable — as an override, never as the default operand.
2 · SELECTION = QUERY
solves a, d
A panel binds a selector, not a list of series. The dock filter box is already the right affordance — promote it from a view filter to a selector language: glob on channel, @ predicate on source, optional attribute terms. A panel bound to derived/temp* @ run_* plots 16 series today and auto-joins run_09 the moment it loads. Saved selectors become named sets — they replace FAVORITES (a favorite is just a one-item set).

One syntax everywhere. — Drag a set row onto a panel = bind. Tree stays for browse; the query is for intent.
3 · STYLE BY RULE
solves b
Map visual channels to dimensions; stop assigning colors to series. A panel carries style rules — color ← source — and every series derives its look. Bulk restyle = edit one rule. Color is the only automatic encoding: with the ghost model (§9) doing the differentiating, line style stays flat — hue carries exactly one dimension, never two encodings fighting. The current per-series popover survives as an override stacked on the rules: marked, listed, revertible.

— Rule target: color only (plus opacity for de-emphasis). Maps to source, channel, a set, an attr (unit), or focus order (§9). Dash and width never vary by rule — line style is not a data channel; focus does the differentiating. Both exist solely as manual overrides. — Defaults: ghosted panel → color ← focus order (palette hues assigned as series are pinned). "all" view → color ← the dominant dimension; a second dimension separates by grouped chips or facet split (§7), never by line style. — Overrides target a selector too: "run_07 @ *" can be bolded across every panel in one rule. Overridden series carry a ◆ marker in legend and popover. — Palettes stay in View ▸ Series palette (v2 §4); rules choose the dimension, palette supplies the hues.
4 · LEGEND = MATRIX
solves a, d
The legend is the focus readout, not a roster. Inline chips render exactly what is highlighted in the plot — never "the first 8". Each dimension is a single count token (RUN 8 ▾ … RUN 248 ▾) opening the full roster; the strip is structurally identical at 8 runs and 800. The panel-header chip row collapses the same way: one grouped chip per channel with a source count.

— Roster rows and focused chips are live operands: hover = emphasize that slice (others drop to 25% opacity) · click = focus toggle · ⌥click = mute · chip ✕ = unfocus. Mixer semantics — run_412 is as reachable as run_01: type in the roster's selector box, click, done. — Grouped chip ▾ expands the source list in place for per-series reach (remove one run, override one series). — Cursor popup (v2 §2) groups the same way past 12 rows: one row per channel, value range across sources, expandable. — No first-N enumeration, ever. The count token's popover is a virtualized, selector-searchable roster carrying the full hue/rule key. Inline chips are the focus stack (§9) verbatim — small by design; past ~8 focused, +n. The strip is one line, never wraps, never scrolls. — Hard rule: no UI surface may render one element per series — or per dimension value — unbounded. Everything groups or collapses past a threshold.
5 · CHANNEL MAP
solves c
Name drift gets a mapping layer, not a rename. The screenshot already shows the disease: temp (8 runs) and temperature (7 runs) are the same quantity. A workspace-scoped channel map aliases source-local names onto one canonical channel — non-destructive, serialized, and the canonical name is what selectors, rules, legends, and the tree all speak.

6 · TABLE MODE
solves b, d
Past a few hundred series the tree is for browsing, a table is for operating. The signals dock gains a second mode: a virtualized flat table of every series (or every channel, toggled), sortable and column-filterable, with real multi-select. Bulk actions operate on the selection — this is where "select 142 things and act once" lives.

7 · FACET SPLIT
pressure valve
When one plot with 64 series is still unreadable, fan it out. Panel header gains "split by ▸ source · channel": the panel becomes a grid of small multiples, one per dimension value, sharing the time axis and y-range (link toggle). It is a view of the same binding — unsplit restores the overlay. This replaces manually building 8 panels to compare runs.
— Facet cells inherit the panel's rules minus the split dimension (split by source → color remaps to channel inside each cell). — Cap the grid (e.g. 16 cells); past it, page or demand a tighter selector. Never render 400 miniature plots. — Cursor track spans all cells at the shared t. Measure stays per-cell.
8 · ROLLOUT
order matters
P1 — model. series = channel × source in the data layer; panels store selectors + overrides instead of series lists. Pure refactor, UI unchanged. Everything else depends on it. P2 — selector + sets. Filter box grammar, saved sets replace favorites, ⌘P shares the grammar, drag-set-to-panel. P3 — rules + legend. Dimension-mapped styling, override stack, matrix legend, grouped chips, solo/mute on legend keys. P4 — table mode. Virtualized table, multi-select, bulk bar. P5 — channel map + facets. Alias layer with near-match suggestions; split-by small multiples.
ACCEPTANCE ▢ Load 20 sources × 500 channels: dock interactive < 100 ms, no per-series UI element anywhere unbounded. ▢ Recolor all runs in a 64-series panel: one action, < 5 s. ▢ temp / temperature / T_amb plot as one channel after one merge; originals recoverable. ▢ Isolate run_07 across a full workspace: one legend click. ▢ Workspace round-trips selectors, sets, rules, overrides, and the channel map.
9 · GHOST BY DEFAULT
amends §3 · solves a
Arrival earns a ghost; focus earns color. Dropping a bundle renders every series as a thin neutral ghost — one non-color, no hues, no legend roster. The bundle reads as an envelope: shape, spread, outliers. Color is granted only through focus, a small per-panel stack of series or slices, and the style rules (§3) apply to focused series alone. Isolating 1 of 64 is hover + click, not 63 removals.
— Threshold: a drop of ≤ 4 series auto-focuses all of them — small drops behave exactly like today. Above it, the bundle arrives fully ghosted, focus empty. — Acquire focus, exploration-first: hover any ghost = temporary emphasis + name tag (nearest-line hit test, generous tolerance) · click = pin to focus · legend key click = focus a slice (run_07, or channel temp) · Tab / ⇧Tab walk neighboring ghosts by value at cursor t · esc clears · ⌥click = mute (drop from ghosts entirely). — Ghost rendering: fg-4 @ 1 px, ~50% opacity, solid — ghosts carry no per-series styling. Ghosts stay hit-testable; the cursor popup collapses them to one row: 15 ghosts · 1.48 → 1.71, expandable. — Escape hatch: panel-header "all" toggle rules-colors everything for the rare true-spaghetti read. The focus chip (focus 2/16) shows state either way. — Focus stack and all/ghost toggle are per panel, workspace-serialized.
