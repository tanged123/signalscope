AUDIT V2 SignalScope — chrome + rendering audit 2026-07-25 · build screenshot 14:17
Amends AUDIT v1 where noted. Standing rules unchanged: chrome is three strips (title bar · tab strip · status bar), no toolbar; chrome holds nouns and toggles, one-shot verbs live in the palette; document-scoped controls live on the panel header; ⌘P = go-to-signal, ⌘⇧P = commands, hinted once; gesture legend is contextual only.
1 · RENDER CLIP
severity: defect
Series paint below the x-axis spine. Data must never render outside the plot rect — not into the gutter, not over the axis, not under other panels.
— Clip the series layer (lines, fills, markers, cursor hairline, annotation carets) to the axes rect. One clip region per panel. — Out-of-range data is cut at the boundary, never redrawn or rescaled silently. — Axis spines, ticks, and labels render outside/after the clip — they are chrome, series never overpaint them. — Applies identically in gutter and inline axes modes; inline tick labels keep their translucent backing above series.
2 · CURSOR = POPUP
amends v1 ④
Agreed — the in-plot popup is the cursor readout. It sits at the point of attention; a status-bar value cluster would split it again. v1's "cursor cluster bottom-right" is withdrawn; only the time scalar survives in chrome (finding 5).
Cursor is modal, default none — no clutter until asked:
none (default) — nothing renders. Status bar shows no cursor item. track — hairline + popup: t header, one row per visible series (swatch · path · value %.4f, tabular, right-aligned), legend order. Offset 12px from hairline, flips side near plot edge, never under the pointer, clipped to panel. measure — two anchors + Δ chip (Δt · Δv · slope). Click drops numbered annotations, as built. — C cycles modes (or per-panel header toggle). Mode is per-workspace, serialized. — DELETE: toolbar "cursor |" item and status-left "cursor t = —". No persistent per-signal readout anywhere in chrome — the tree's live-value column already covers "values now".
3 · TIME = ONE CLUSTER
amends v1 ① ②
Correct instinct: all time state lives in one place. Today it is scattered (window t top-right, cursor t bottom-left, Linked t toolbar, FOLLOW top-right). Consolidate into a single time cluster on the status-bar right — the editor-caret position, which for this tool IS time. This supersedes v1 putting window t on the title bar and Linked t on the tab strip.
— Order, left→right: ⛓ linked · t 9.9661 · window 0.000 → 20.000 s · ⏸ FOLLOW — ⛓ linked: workspace-scoped toggle; active = achromatic fill (surface-4 + fg-1), inactive = dim glyph. — t: cursor time; renders — when cursor mode is none. Click → jump-to-t input. — window: live during pan/zoom; click → exact-range input. FOLLOW stays a reserved slot for streaming. — Title bar right now holds only OS window controls. Tab-strip right holds only "layout ▾".
4 · MENU BEHIND ≡
new · Zed pattern
Adopt Zed's hidden menu: the top-left logo block becomes ≡; click opens the menu, otherwise no menu bar exists. The menu is the browsable mirror of the palette — every item is also a ⌘⇧P command; nothing lives only in the menu. Four menus, not seven. Cut: Edit (no text-document model; view undo/redo are palette commands + keys), Signals (signal detail belongs to the tree context menu and a future signal inspector, not global chrome), Panel (verbs live on the panel header), Export as top-level (nests under File).

5 · STATUS DOTS: CUT
amends v1 mockups
The dots were over-applied — remove them. A status dot means connection state. A loaded file has no connection state, so ● demo_flight.csv communicates nothing and adds a green light to every session. Files render as demo_flight.csv · 656 pts, no indicator. Dots return only when streaming ships, exclusively on live sources: connected green · connecting yellow · error red. No other decorative indicators anywhere — if it does not encode state that can change, it does not render.

8 · IMPLEMENTATION
high-level, in order
P1 — chrome re-home (layout only, no new behavior). Delete the toolbar row. Title bar: ≡ button · wordmark · session name · OS controls. Tab-strip right: layout ▾ only. Status bar: [dock toggles | source truth] left · [gesture hint | cursor mode | time cluster | ⌘P hints] right. Every relocated control keeps its existing handler. P2 — render clip. One clip region per panel = axes rect. Series, markers, hairline, annotation carets inside; spines/ticks/labels outside. Verify in gutter and inline modes. P3 — cursor state machine. Modes none | track | measure, per workspace, C cycles, serialized. Track = hairline + popup (12px offset, edge-flip, panel-clipped, legend order, %.4f tabular). Measure = existing anchors + Δ chip + click-to-annotate. Delete the toolbar cursor item and status-left readout. P4 — command registry + ≡ menu. Single registry: every action defined once {id, title, section, keybinding}; ⌘⇧P and the ≡ menu are two views of it — nothing is menu-only. Menu tree per finding 4. Then workspace serialization (layout + panels + signals + window + cursor mode + annotations) under File; global prefs (theme · font size · palette · axes default) under View, persisted across sessions. Future HTML snapshot export/import = the same workspace object, also under File. P5 — polish. Remove file status dots (streaming-only later). Gesture legend → single contextual hint while dragging. ⌘P retargets to go-to-signal; ⌘⇧P commands. FOLLOW stays a reserved dim slot.
Acceptance: no toolbar row exists · no series pixel renders outside any plot rect · time appears in exactly one cluster (plus the transient popup/Δ overlays) · a fresh session with cursor none shows zero readouts, dots, or hints beyond source truth · each ⌘P/⌘⇧P hint renders once · every ≡ menu item is invocable from ⌘⇧P.
