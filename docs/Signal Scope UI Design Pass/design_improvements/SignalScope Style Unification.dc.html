That is not two features; it is one feature with no resolution order.

2 · THE LAW
three scopes, one order
Every visual property resolves through the same three-step cascade, and each editor sits at exactly one step. Nothing is duplicated because nothing is co-located: the toolbar cannot set a per-series value, the row inspector cannot set a set-wide one. Later steps win, and the winning step is always shown next to the value.
STEP 1 · PANEL DEFAULT
the toolbar
One value for the whole plot. Line width, curve, ghost strength, y-scale, cursor, decimation. Answers how this panel draws. §3
STEP 2 · ENCODING RULE
the legend header
A property bound to a dimension: color ← source, dash ← channel. Carries the palette. Answers what the colors mean — which is the definition of a legend. §4
STEP 3 · SERIES OVERRIDE
the legend row
A literal value pinned to one series, breaking it out of the rule on purpose. Always marked, always counted, always one click from revert. §5
CONSEQUENCES — THESE ARE THE ACCEPTANCE CRITERIA — Steps 2 and 3 both live in the legend. That is not a duplication; the legend is the only surface that is per-series and per-set, so both editors dock to it and the precedence is visible in one glance. — The toolbar loses every per-line control it never had a right to, and gains the panel-wide ones that currently have no home. Its binding chip stops re-listing series. — An overridden field never silently shadows a rule. The row shows ▍ at the field, the legend footer counts n overrides ▾, and changing a rule leaves overrides alone but flashes the count. — The row inspector is not a floating card. It expands the row in place, so it works identically floating, docked to a rail, and at 140 px. Popover-over-popover is deleted. — Derivation is not the panel's business at all. d/dt · ∫dt · smooth · |x| leave the product surface here entirely — the signal-derivation feature emits derived signals upstream and they arrive as ordinary bindable signals. §7

7 · DERIVE LEAVES
shot 4 cleanup
Cut the four transform buttons and add nothing in their place. Signal derivation is an existing upstream feature that emits a first-class signal; a plot-local derivative would be a second, weaker copy of it — unnamed, unqueryable, invisible to the signal tree, absent from every other panel, and dead on rebind. There is no derive bar, no DERIVED group, no dash ← derived rule.
— A derived signal reaches a panel the way every other signal does: it is bound. It occupies an ordinary legend row, takes a palette slot, and is focused, muted, and overridden by the same rules — the panel does not know it is a derivative, and does not need to. — The only residue: a binding whose glob matches a derived signal's path picks it up automatically, so d_response ×8 is a normal binding chip. — If an operator reaches for a derivative from the plot, the right affordance is a link out to the derivation feature with the signal pre-filled — not evaluated here. Flagging it rather than designing it.
8 · STATS ARE COLUMNS
replaces the bottom strip
The stats strip is a legend with the rows taken out. It lists one entry per series, keyed by color, printing per-series numbers — that is the legend's job description. Today it is a second, worse copy: it wraps instead of scrolling, it cannot be sorted, searched, focused or muted, it repeats the name the legend is already showing, and it grows the panel from the bottom so the plot resizes when a feature is switched on. At 8 series it costs two lines. At 1000 it costs 250.
So do not build a stats surface. Add stat columns to the legend rows and delete the strip. Every scale problem is then already solved by machinery that exists: virtualization, the selector, grouping, focus, override marks, the size ladder. Σ in the toolbar toggles the columns on; the legend widens to fit them and nothing else in the panel moves.
A · NOTHING REFLOWS THE PLOT WITHOUT A DRAG — Overlay is the only default. Turning any feature on — stats, roster, selector — may cover plot area but may never resize it. A plot that changes size when you ask a question about it invalidates the comparison you were making. — Docking is a deliberate gesture, and the legend already has it: drag to a panel edge and it becomes the rail, the plot reflows once, and that is remembered. Stats columns ride along — the rail is the natural home for a wide stats table, but only because the operator put it there. — The bottom strip is deleted outright. The status bar keeps the two facts that are about the plot rather than the series: n pts · render ms and the cursor readout.

At scale nobody reads 1000 rows — they ask which one. Sort by a column and the answer is row one. The ∑ row's spark-histogram is the distribution of the sorted statistic across the whole set, and clicking a bar selects that bucket: the only stats interaction that gets better as N grows. Group headers carry the same columns aggregated, so a collapsed group still answers the question.
Generic across plot kinds. Do not define "time-series statistics". Define statistics over a sample set on an axis, and let the plot's axis kinds decide which blocks appear. Every plot type is then covered by the same table and the same column picker — an x/y plot shows two distribution blocks instead of one, and time series get a domain block because their x axis is ordered and regular.
BLOCKCOLUMNSAPPEARS WHEN
distributionn · min · max · μ · σ · rmsalways, once per quantitative axis. Prefixed when there are two: x.μ / y.μ. The default visible set.
domainspan · Δ · rate · gapsan axis is ordered and monotone — true of time, also of a swept parameter. Never for scatter.
at-cursor@cur · Δ vs. refa cursor exists. On an ordered axis it interpolates at the cursor's position; on a scatter it reads the nearest point. Same column, two resolvers.
extremesargmin · argmaxthe where of min/max, in the other axis's units. Opt-in; the column that answers "when did it peak".
pairwiser · slope · rmse · Δμtwo rows are selected, or a row is marked as reference. Rendered as a footer block, not a column — it is a relation, not a property.
shapep05 · p50 · p95 · sparkopt-in. Percentiles are the honest summary for non-normal data, and the sparkbar makes the row scannable before the digits are read.
MECHANICS — Scope is stated, never assumed: the header carries Σ visible region ▾ (visible region · full record · selection). Recomputed on pan and zoom, and the header flashes while a recompute is in flight so a stale number is never read as current. — Columns drop right-to-left exactly as the tree-table does, in reverse picker order; the name column and the sorted column never drop. ⊞▾ is the picker. — Units follow the axis, printed once in the column header (MAX (m/s)), not per cell. Mixed units in one column show the value with a dimmed per-row unit and disable sorting with a stated reason. — 4 significant figures, tabular numerals, right-aligned, sign-aware column width so the digits stay in a column when a minus appears. — ⤓ csv in the footer exports exactly the visible columns for the current scope — the one thing the old strip was being copy-pasted for.
